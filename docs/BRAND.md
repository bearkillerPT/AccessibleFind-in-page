# Accessible Find brand guide

Accessible Find exists so that people with low vision can find text on a page. The brand follows from that: every visual choice should make things **easier to see**, never just prettier.

## Name and voice

- **Name:** Accessible Find. The full name, "Accessible Find in Page", appears only in store listings.
- **Tagline:** *Find in page, made visible.*
- **Voice:** plain, warm and direct. Short sentences and everyday words. Explain what happens and why ("Browsers don't let extensions run on their own pages"), never blame the user, and never use jargon like "host permissions" or "content script" in the UI.

## Logo

| File | Use |
| --- | --- |
| `assets/brand/icon.svg` | Master icon. Used for 48 px and larger. |
| `assets/brand/icon-small.svg` | 16 and 32 px. No text lines, heavier strokes, so it stays crisp. |
| `public/icon/{16,32,48,128}.png` | Generated by `npm run icons`. Don't edit by hand. The 128 px one has 16 px of transparent padding around 96 px artwork, as Chrome and the Web Store expect; in the UI, use `icon.svg`. |

**Construction:** a beam-yellow magnifying glass on a night-blue rounded square (radius 28/128). Inside the lens, an orange bar stands for the highlighted match, with grey lines of text above and below it. The icon is the product in one glance: a match standing out from the text around it.

**Don'ts:** don't recolor the icon or put it on a busy background. Don't add a drop shadow inside the square, and don't use it smaller than 16 px.

## Color

| Token | Hex | Role |
| --- | --- | --- |
| Night | `#0B1020` | Brand background, dark theme canvas, light theme ink and buttons |
| Beam | `#FFD60A` | Primary accent: dark theme buttons and focus ring, logo |
| Signal | `#FF8A00` | Secondary accent: icons, the current match, the "highlighted" bar in the logo |
| Mist | `#F4F6FC` | Light theme canvas, dark theme text |

The full light and dark palettes are the CSS variables in `src/styles/globals.css` (shadcn/ui tokens).

**Contrast rules:**

- Body text is at least 7:1 against its background; muted text is at least 4.5:1.
- Control borders (`--input`) are at least 3:1 against the surface they sit on (WCAG 1.4.11).
- Beam yellow is never used for text on light backgrounds. In the light theme, primary buttons are night-blue with yellow text, and the focus ring turns burnt orange (`#B45309`).

## Typography

**Atkinson Hyperlegible Next**, by the Braille Institute, designed for readers with low vision. Similar-looking characters (I, l, 1; O, 0) are clearly distinct. It's used for all UI and the in-page magnifier. It ships in `public/fonts/` (SIL Open Font License, see `public/fonts/OFL.txt`), and the fallback is the system UI font.

- Headings: bold, slightly tight tracking.
- Body: regular, generous line height (1.5 or more).
- Numbers that change (match counts, values) use tabular figures.

## UI principles

1. **Everything scales.** All sizes are in `rem`, and the text-size preference sets the root font size of every extension page. Default is 125% (20 px).
2. **Focus you can't miss.** A 3 px solid ring in the ring color with a 2 px offset. Never remove focus styles.
3. **Never color alone.** Matches are underlined as well as colored, the current match has a border, and toggles show a filled state *and* `aria-pressed`.
4. **Big targets.** Controls are at least 40 px at the default text size.
5. **Calm motion.** Blinking stays under 3 flashes a second (WCAG 2.3.1), and all animation stops when the OS asks for reduced motion.
6. **Dark first.** The find bar was designed around the dark theme (less glare for light-sensitive eyes); the light theme is fully supported.
7. **Real semantics.** Headings are headings, labels are labels, live regions announce match counts.

## Components

The UI uses [shadcn/ui](https://ui.shadcn.com) (style `radix-nova`, Radix primitives) with Tailwind CSS 4. Components live in `src/components/ui/` and are ours to change. Accessibility changes made to the generated components:

- Focus rings are fully opaque with an offset (shadcn uses 50% opacity).
- Switch and slider are sized in `rem` with larger thumbs, so they scale with text size.
- Toggles show a filled primary background when on.
- `CardTitle` renders an `<h3>` (shadcn renders a `<div>`).
- Slider thumbs take an accessible name and a spoken value with units.
- The input inside an `InputGroup` has no ring offset of its own: the group draws the focus ring, and the offset would paint over its border.
- Inputs keep the same text size at every window width (shadcn makes them smaller on wide screens); the text size preference decides.
- Hover cards have a solid 2 px border and only fade in (no zoom or slide). They show examples of effects (`SwitchField`'s `example`), drawn live in the user's own colors. A small help button (?) beside the field's label opens them: on hover, on keyboard focus, or with a click or tap. Hovering the rest of the field does nothing. They sit beside the field, let the pointer pass through so they never block the next switch, and never hold the only copy of anything: the label and description still say what the setting does.

After `npx shadcn add <component>`, apply the same treatment to the new component.

## Default highlight colors

These are the out-of-the-box find colors. They're also the brand's "find" palette in screenshots and marketing.

| Element | Color |
| --- | --- |
| Match | yellow `#FFFF00` background, black text, orange `#FF8C00` underline |
| Current match | orange `#FF8C00` background, black text, yellow `#FFFF00` border |
| Magnifier | night background, white text, current-match border |

## Assets

- `npm run icons` regenerates the PNG icons from the SVGs.
- `SCREENSHOTS=<dir> npm run test:e2e -- screenshots` captures 1280×800 screenshots (dark and light) for review and the README.
- `npm run store-assets` renders the Chrome Web Store images into `store/`: five captioned screenshots, the promo tiles and the store icon. Captions follow the voice above, with one phrase marked like the current match. `store/LISTING.md` has the listing text.
- `npm run store-video` records `store/demo.mp4`, the listing's demo video: the real extension in each scene, under the same captions, between a title card and an end card. Silent, 1920×1080, about 50 seconds.
